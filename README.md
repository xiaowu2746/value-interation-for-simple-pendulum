# Value Iteration for Simple Pendulum

This project implements a grid-based value iteration controller for a torque-limited simple pendulum. The controller computes a global cost-to-go table over the pendulum state space and extracts a lookup-table feedback policy for swing-up and stabilization near the upright equilibrium.

The implementation is intentionally kept as a small Python project rather than a notebook. Simulation results, plots, CSV files, and GIF animations are generated by running `main.py`.

## Features

- Nonlinear simple pendulum dynamics with torque input.
- Discretized state space over angle and angular velocity.
- Discrete torque grid with 9 input values from `-3 Nm` to `3 Nm`.
- Vectorized value iteration using `numpy`.
- Two cost functions for comparison:
  - `minimum_time`
  - `quadratic`
- Closed-loop simulation from a downward initial condition.
- Generated result figures:
  - value function heatmap
  - policy heatmap
  - state trajectory plot
  - torque input plot
  - value iteration convergence plot
  - pendulum swing-up GIF

## Model

The pendulum state is:

```text
x = [theta, theta_dot]
```

In this code, `theta = 0` is the upright equilibrium and `theta = pi` or `theta = -pi` is the downward position. Angles are wrapped to `[-pi, pi)`.

The dynamics are:

```text
theta_dot = omega
omega_dot = g / l * sin(theta) + u / (m * l^2) - b * omega
```

The default parameters are defined at the top of `main.py`:

```python
N_THETA = 81
N_OMEGA = 81
OMEGA_MAX = 8.0

MASS = 1.0
LENGTH = 0.5
GRAVITY = 9.81
DAMPING = 0.05

INPUT_LIMIT = 3.0
INPUT_GRID = tuple(np.linspace(-INPUT_LIMIT, INPUT_LIMIT, 9))

DT = 0.05
SIMULATION_TIME = 8.0
MAX_ITERATIONS = 700
```

The torque grid is:

```text
[-3.00, -2.25, -1.50, -0.75, 0.00, 0.75, 1.50, 2.25, 3.00]
```

## Method

The state space is discretized into a two-dimensional mesh over `(theta, theta_dot)`. For every grid state and each torque input, the next state is computed with fourth-order Runge-Kutta integration and mapped back to the nearest grid point.

Value iteration applies the Bellman update:

```text
J_new(x) = min_u [g(x, u) + gamma * J(f(x, u))]
```

After convergence, the policy is extracted by selecting the torque that minimizes the Bellman objective at each grid point:

```text
policy(x) = argmin_u [g(x, u) + gamma * J(f(x, u))]
```

The final controller is a lookup-table feedback policy. During simulation, the continuous state is mapped to the nearest grid point, and the corresponding torque is applied.

## Installation

Create a virtual environment and install dependencies:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

## Run

Run the default experiments:

```bash
.venv/bin/python main.py
```

The script runs both `minimum_time` and `quadratic` cost functions. To change grid size, physical parameters, simulation time, or input limits, edit the parameter block at the top of `main.py`.

## Outputs

Generated files are written to `results/`.

For each cost function, the project saves:

- `*_trajectory.csv`: closed-loop trajectory data
- `*_value_function.png`: value function heatmap
- `*_policy.png`: feedback policy heatmap
- `*_states.png`: angle error and angular velocity over time
- `*_torque.png`: torque input over time
- `*_convergence.png`: Bellman update convergence curve
- `*_animation.gif`: pendulum swing-up animation

Summary files:

- `results/summary.md`
- `results/summary.json`

Example default result:

```text
minimum_time:
  final theta error = -0.1178 rad
  final theta_dot   = -0.1199 rad/s
  first entered target neighborhood = 2.95 s

quadratic:
  final theta error = -0.1462 rad
  final theta_dot   = -0.1941 rad/s
  first entered target neighborhood = 3.0 s
```

## Interpreting the Figures

- `value_function.png` shows the cost-to-go from each state. Lower values indicate states that are closer or easier to drive to the upright target region.
- `policy.png` shows the selected torque for each state. Strong red/blue regions indicate bang-bang-like behavior.
- `states.png` shows whether the pendulum reaches the upright neighborhood and whether angular velocity is reduced.
- `torque.png` shows the discrete control inputs selected by the policy.
- `convergence.png` shows the maximum Bellman update at each iteration. A decreasing curve indicates convergence of the value function.
- `animation.gif` visualizes the closed-loop swing-up motion.

## Notes

This controller is approximate because both state and input spaces are discretized. It normally converges to a small neighborhood of the upright equilibrium rather than exactly to `theta = 0, theta_dot = 0`. A common improvement is to use value iteration for global swing-up and switch to a local LQR or PD controller near the upright point.
